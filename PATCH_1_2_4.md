# PATCH 1 + 2 + 4 — MOSTIK

## 1. Дубликаты животных
- Клиент нормализует список животных перед отображением: повтор одной и той же записи по ID не показывается дважды.
- Дополнительно схлопываются явно одинаковые карточки по владельцу + имени + виду + породе/подвиду + дате рождения + микрочипу.
- API `GET /animals` защищён от размножения строк из `animal_access` через `DISTINCT ON (a.id)`.

## 2. Стабильность SPA
- Роутер `view()` теперь имеет error boundary.
- Синхронные ошибки и rejected Promise от экранов перехватываются.
- Вместо белого экрана показывается понятное состояние ошибки с кнопками «Повторить» и возврата в рабочий раздел.
- `enhanceSmartFields()` также защищён от ошибки, чтобы вспомогательная обработка формы не ломала экран.
- Ошибки остаются в console/telemetry для диагностики.

## 4. Демо-данные для Байкала
Добавлена миграция `050_demo_baikal_enrichment.sql`:
- полноценный активный план питания Байкала с целевой калорийностью;
- период рациона, 3 приёма пищи и продукты;
- существующие демо-записи питания Байкала связаны с планом и заполнены продуктами;
- 3 дополнительные наблюдения с разными датами для аналитики;
- дополнительная недавняя завершённая тренировка и повторения навыков.

Миграция идемпотентна и не затрагивает реальных животных/пользователей.

## Проверка
`node --check` успешно пройден для:
- `app.js`
- `public/app.js`
- `api.mjs`

После применения миграций рекомендуется открыть демо-владельца и проверить «Животные», «Журнал», «Рацион», «Тренировки» и «Аналитика».
