MOSTIK v5.3.27 — встроенные окна вместо alert() / confirm() / prompt()
======================================================================
Включает v5.3.25 и v5.3.26. Копировать поверх v5.3.26.

ЗАЧЕМ
-----
В приложении было 93 alert(), 26 confirm() и 18 prompt() браузера. Они блокируют
экран, выглядят чужеродно (особенно на телефоне и в PWA), показывают сырые тексты
ошибок сервера и заставляли вводить служебные значения руками
(например «normal / attention / critical» или дату «ГГГГ-ММ-ДД»).

ЧТО СДЕЛАНО
-----------
Новый слой в app.js (рядом с toast): uiNotify, uiAlert, uiConfirm, uiPrompt,
uiChoice, uiForm. Все окна: role=dialog/alertdialog, aria-modal, фокус внутри окна
(Tab по кругу), Esc = отмена, возврат фокуса на кнопку-источник, текст экранируется.

1. alert -> toast (93 вызова)
   - ошибки (e.message и т.п.)      -> красный toast, держится не меньше 5 с
   - «Настройки сохранены», «Сохранено», «Пользователь создан» ... -> зелёный toast
   - проверки полей («Заполните поля», «Укажите …») -> жёлтый toast
   - длина сообщения увеличивает время показа (до 10 с); клик закрывает toast
   - инструкции по установке PWA (5 мест) -> окно «Установка приложения»
   - НОВЫЙ КОД ВОССТАНОВЛЕНИЯ пользователя -> окно с кнопкой «Скопировать код»;
     его нельзя закрыть Esc или кликом мимо — код не потеряется
2. confirm -> окно подтверждения (26 вызовов)
   - заголовок = вопрос, пояснение отдельной строкой
   - кнопка называется по действию: «Удалить», «Убрать», «Сбросить», «Выйти» ...
   - для удаления кнопка красная, фокус по умолчанию на «Отмена»
3. prompt -> формы (18 вызовов)
   - Статус животного: три радиокнопки с русскими названиями
     (раньше нужно было набрать normal / attention / critical)
   - Новый план питания: одна форма (название, дата начала, дата окончания,
     целевой калораж) вместо 4 подряд идущих prompt; дата окончания не может быть
     раньше начала
   - Новый период плана: форма с двумя датами (календарь вместо «ГГГГ-ММ-ДД»)
   - Копировать день: одна форма (из какого дня, в какие дни)
   - Применить шаблон рациона: выбор из списка вместо «введите номер»
   - Целевой калораж: числовое поле; название шаблона/плана, свой вид/подвид,
     «Другое…» — обычные поля с проверкой «поле обязательно»

ИЗМЕНЕНИЯ ПОВЕДЕНИЯ (осознанные)
--------------------------------
  - Отметка ДЗ выполненным (owner/vet): раньше «Отмена» в prompt всё равно
    отмечала ДЗ выполненным. Теперь «Отмена» отменяет действие, заметка необязательна,
    кнопка «Отметить выполненным».
  - Даты по умолчанию в новых формах — по местному времени, а не UTC.
  - 4 обработчика событий стали async (сброс настроек, «Другое…» в двух местах,
    выбор своего вида/подвида) — им нужно ждать ответа окна.

Файлы: app.js, app.css, sw.js (в корне и public/), кэш SW -> mostik-v5.3.27-cache.
No DB migrations in this patch.

ПРОВЕРКА
--------
  1. Животные -> значок статуса -> три варианта с русскими названиями.
  2. Администрирование -> «Новый код восстановления» -> окно с кнопкой копирования;
     Esc/клик мимо не закрывают.
  3. Удалить любую запись -> красное окно «Удалить …?», фокус на «Отмена».
  4. Рацион -> План питания -> «Создать» -> одна форма; поставить дату окончания
     раньше начала -> сообщение об ошибке.
  5. Отключить сеть и нажать любое сохранение -> красный toast вместо alert.
